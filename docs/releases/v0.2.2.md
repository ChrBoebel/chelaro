# Chelaro v0.2.2 — Automatic Update Proof Candidate

Status: release-ready source; unpublished binary. Version `0.2.2` is intentionally separate from
the signed `0.2.1` bootstrap so both releases can be immutable and the owner can exercise the real
macOS automatic-update path.

## Included

- synchronized `0.2.2` versions in the root, desktop, and web packages;
- the same public GitHub Releases provider and explicit user-controlled update flow as `0.2.1`;
- a protected release environment requiring owner approval and allowing only `v*` tags;
- bounded standalone dependency completion that cannot recurse through old desktop packages;
- no database migration, finance mutation, credential migration, or document-format change.

## Local package evidence

The unsigned local package is not a distributable release, but it validates the source artifact
before signing:

- the packaged bundle reports `0.2.2` and contains the public GitHub update provider;
- DMG, ZIP, ZIP blockmap, and `latest-mac.yml` were produced for Apple Silicon;
- the packaged API, Agent Host, and standalone web runtime started successfully;
- a synthetic finance-assistant E2E reused the existing Codex login, preserved canonical data until
  owner approval, then created one receivable with its linked audit event;
- the live updater reached GitHub and correctly reported that no public release exists yet.

Developer ID signing, notarization, Gatekeeper verification, and the online `0.2.1` to `0.2.2`
update remain release-workflow gates rather than claims of this local package.

## Required publication order

1. Configure all five Apple secrets in the `macos-release` GitHub environment.
2. Tag the immutable `0.2.1` merge commit and approve its protected deployment.
3. Verify the signed, notarized, stapled, and checksummed `v0.2.1` release.
4. Install the verified `v0.2.1` DMG manually without deleting the established local data path.
5. Tag the immutable `0.2.2` merge commit and approve its protected deployment.
6. Verify the complete stable `v0.2.2` update artifact set before starting Chelaro `0.2.1`.

Never reverse this order and never replace assets inside an existing GitHub Release.

## Owner automatic-update test

Use synthetic data only.

1. Start the signed installed `0.2.1` and confirm existing synthetic records are present.
2. Wait for the startup check or reopen Chelaro, then confirm the update control announces `0.2.2`.
3. Start the download and confirm installation remains an explicit owner action.
4. Install and let Chelaro restart.
5. Open **Chelaro → About Chelaro** and confirm version `0.2.2`.
6. Confirm the established local database, documents, proposals, audit events, Codex login reuse,
   and consent state remain intact.
7. Create and approve one synthetic receivable proposal, then confirm its linked audit event.

## Rollback boundary

Do not downgrade an updated client and do not replace or delete local data. If `0.2.2` is unsafe,
withdraw it from latest promotion and publish a higher signed patch containing the revert or fix.
Preserve both release artifacts and workflow evidence for investigation.
