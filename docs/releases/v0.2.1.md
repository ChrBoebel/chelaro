# Chelaro v0.2.1 — Automatic Update Proof Candidate

Status: release-ready source; unpublished binary. The version is prepared for the first signed
automatic-update proof, but the GitHub Release must not be created until the protected
`macos-release` environment contains all Apple credentials and the workflow verifies the complete
artifact set.

## Included

- isolated GPT-5.6 finance routing with exactly the bounded Chelaro finance tools;
- restored creation of reviewable receivable proposals from natural-language requests;
- proposal-only mutations that preserve explicit owner review before canonical changes;
- a headless embedded API that no longer appears as a second Dock application;
- synchronized `0.2.1` versions in the root, desktop, and web packages;
- a required CI gate that rejects every pull request into `main` without a higher stable product
  version;
- the existing public GitHub Releases update provider and explicit user-controlled update flow.

## Required signed baseline

Electron and electron-builder require the running macOS application to be code-signed for automatic
updates. An ad-hoc local package is therefore not a valid update baseline.

Before testing this release, install a Developer-ID-signed and notarized `0.2.0` once from its
verified DMG. Do not remove `~/Library/Application Support/Finance OS/`; the application bundle and
local financial data are separate.

## Owner update test

Use synthetic data only.

1. Confirm the installed signed baseline reports version `0.2.0` and contains
   `Contents/Resources/app-update.yml`.
2. Confirm the stable GitHub Release `v0.2.1` contains the DMG, ZIP, ZIP blockmap,
   `latest-mac.yml`, and checksums.
3. Start Chelaro and use its explicit update control.
4. Confirm the app announces `0.2.1`, downloads it, asks before installation, and restarts.
5. Confirm the restarted application reports version `0.2.1`.
6. Confirm synthetic documents, proposals, audit events, Codex login reuse, and consent state are
   unchanged.
7. Create and approve one synthetic receivable proposal to verify the finance path after updating.

## Current local limitation

The owner machine currently has an ad-hoc-signed `0.2.0` application with no Developer ID team and
Gatekeeper rejects that bundle. It cannot provide trustworthy automatic-update evidence. There is
also no valid code-signing identity in the local keychain, so a secure baseline cannot be produced
locally without the Apple release credentials.

## Local verification evidence

The unsigned local `0.2.1` verification build completed on 2026-08-31 and produced the DMG, ZIP,
ZIP blockmap, DMG blockmap, and `latest-mac.yml`. Both the unpacked application and ZIP contain the
public GitHub `app-update.yml`, and the bundle reports version `0.2.1`.

The packaged synthetic Finance Assistant E2E passed against dynamically allocated loopback ports.
It verified streamed output, shared Codex login reuse, one review proposal, unchanged canonical data
before approval, owner approval, and an audit event linked to the resulting receivable.

The same run reached the public updater channel and reported `No published versions on GitHub`.
That is the expected pre-release result and proves neither download nor installation. The real
automatic-update proof remains blocked by the signing and publication checklist below.
